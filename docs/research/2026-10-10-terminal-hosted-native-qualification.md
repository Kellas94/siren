# Bounded hosted Windows native qualification

This continues the approved local Terminal host shutdown qualification after host Windows Application Control blocked the unsigned test observer and two administrator Sandbox requests were canceled. No laptop protection is disabled. The fallback uses a separate standard hosted Windows2025 VM with fixed test inputs, not a self-hosted runner or user project.

The probe workflow is restricted to Kellas94/siren branch probe/terminal-roster-20261010. It uses contents:read, disables persisted checkout credentials, checks out the actual run commit, and has no secrets, deployment or product activation step. Native payloads are fixed Node fixtures. Job timeout10 minutes; raw evidence retained three days. Network is used for standard checkout/setup and exact official Node headers/import library; this CI environment is not claimed to be air-gapped. Existing local Sandbox bundles/reviews remain immutable.

The builder checks exact unchanged ownership.cc/peer-endpoints.inc source hashes and Node24.16.0 x64 release input digests against the official SHASUMS. It discovers installed MSVC/SDK on the hosted image, records selected tool identities and compiler-reported headers, scopes PATH/INCLUDE/LIB for compilation, refuses unexpected CL/LINK options and restores the environment. This is selected build provenance, not complete transitive toolchain closure. Build success remains COMPILED_NOT_RUNTIME_QUALIFIED.

The existing external C# observer owns a non-inherited kill-on-close Safety Job and atomically contains each suspended worker before resume. Every required process has independently retained HANDLE identity and Job checks. Native deaths/unrelated canary survival are observed before Safety cleanup; cleanup is recorded separately. The batch requires all eight positive cases and two genuine negative controls. A setup timeout is not a JS-hang observation. Worker exit before the protocol now gets a distinct failure; a JS-hang control requires an actual20-second watchdog with a live worker and the after.json phase. The fake-success control requires the actual live-process refusal. Missing, duplicate, reordered or incomplete cases cannot pass. A separate verifier rereads each actual driver and observer record before writing a bounded verification receipt.

An old-expression counterexample reproduced a real harness false PASS: EXTERNAL_WATCHDOG_DEADLINE:before.json had been accepted as the JS-hang negative control. The initial extractor error, corrected RED, original runner and subsequent changes are preserved in the local coordinator evidence. Independent review identified the additional early-worker-exit ambiguity and linker PATH/source-retention concerns; corrections and separate reviewer evidence are retained. These are source/data improvements, not proof of native execution.

Runtime scope remains Node-only, fixed descendant roles, listener/pending accepts, stable duplicate/fenced shutdown and retained-wrapper GC pressure. No real interactive shell/ConPTY, connected authenticated I/O, wrapper finalization, native-delay responsiveness, injected accounting/reap/monitor faults, Electron or whole-app shutdown qualification is implied. Even a passing bounded probe does not activate the installed Terminal/debugger: nativeExecutionAdmitted, hostNativeJoined, sessionCleanupJoined and asyncTeardownAvailable remain false at the product boundary.

Ruling: use a disposable hosted runner for the same bounded approved native experiment instead of repeating canceled administrator requests or changing signing protection. Cost if wrong: the hosted environment may reveal further incompatibilities; those actual failures must remain failures and be retained, rather than manufacturing a native PASS or weakening the gate. No production merge/release is part of this probe.
