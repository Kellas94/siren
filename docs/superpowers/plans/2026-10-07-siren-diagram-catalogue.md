## Intended behavior

One compact Types & templates disclosure in Diagram, plus a New diagram entry on Home for empty projects. Browse exact built-in examples, see honest editing capabilities, then explicitly create a separate diagram. Existing source, pending fields, editor history, saved entities, imported colours, presentation and source references remain intact. Readonly views may browse; creation requires its own native permission. No replacement of the current source, automatic Save, all-view preparation or inherited active-diagram metadata.

## Task1 - finite shared catalogue and parser-safe data

Root owns src/documents/diagram-catalogue.mjs, a build injection helper and model tests. Use reviewed literal entries with namespaced stable IDs (starter/type and template/example), group/title/description/source, reference SHA and truthful native capability notes. At most32 entries, title160 UTF16 units, description512, source8KiB UTF8/200lines each and total128KiB. Deep-freeze own trusted data. Exact lookup refuses unknown IDs; own-data request normalization refuses extra fields/getters/prototypes/malformed Unicode/oversized values. No user-source evaluation, icon fetching, legacy closures or localStorage. Tests start RED for missing contract; assert every exact reference source hash, immutable catalogue, budgets and conservative type/capability wording. Declaration detection must use existing bounded frontmatter/declaration handling; comments/labels cannot spoof a type.

## Task2 - scoped preservation of pending editor fields

Before the catalogue moves focus, implement context-bound beginExternalInteraction leases on Guided/Style and equivalent integration handling for Build/Inspector/title. Acquire before pointer, keyboard or programmatic focus moves. Preserve actual mounted DOM, selection/value/error/source binding and history; suppress only implicit blur/change commits caused by that external interaction. Explicit Apply/Cancel and later Save/prepare validation remain effective. Cancel restores current original focus before release. Successful new native window must keep its focus; the old pending editor resumes safely on genuine return. Leases are idempotent, cannot leak across repeated toggles/context replacement/disposal, and cannot restore private content after Lock. Do not infer IME completion. Actual RED tests must cover valid/invalid fields, focus/selection, composition entry refusal or preservation, multiple gestures, context retirement and explicit prepare handoff.

## Task3 - dedicated native append transaction and operation replay

Root owns a small main-only creation service, explicit WorkspaceCoordinator action, DomainRepository append transaction, IPC/preload wiring and package allowlist. Request exactly {entryId,title,operationId}; main derives project/root/new identity/source/capability. Require current normal schema2 project, authentic native frame, current access epoch and explicit creation policy. Diagram callers must already be admitted working editors; Home has its own deliberately narrow empty-grant exception. Presenter/Audience/foreign/readonly callers never acquire append authority through an edit/read grant. Keep persistence on the existing owner FIFO, byte/pending bounds, guards and transition proof. Private flush tickets cannot authorize creation.

Read verified latest manifest ancestry inside the queue. Resolve trusted catalogue definition into request identity, enforce diagram-count/container/manifest budgets, allocate UUID in main and append one minimal validated Diagram at native version1. Preserve every existing entity/version/order/sourceRef/envelope/opaque value. Commit once against the actual read revision; never rebase a stale whole envelope. Guard final readback and expose actual durability.

Distinct operation marker includes action/project/request hash/catalogue identity/new entity/hash. Verify replay in selected ancestry and use exact historical commitManifest replay without selecting an old revision over later work. Changed-content operation reuse refuses; repeated completion cannot append twice or roll back edits. Historical creation identity and current availability are separate facts. Removed/ambiguous objects cannot be resurrected by opening.

## Task4 - snapshot refresh and real native admission

Update main snapshot/bootstrap from verified current reread without selected(), selectionGeneration/epoch reset, global prepare or existing renderer refresh. Existing grants remain scoped to their old IDs. Open the newly created sibling via main registry, then workingDiagrams.admit with its authentic frame. Track the entire external operation in writes, and the mutation in the owner queue; recheck sender/epoch/roster/barrier/membership after each await. Discard incomplete native surfaces on revocation using existing refusal cleanup. Persistence success with opening refusal is not creation failure: return separate outcomes and main-bound retry for the same creation identity. No arbitrary sibling open permission. Home gets bounded metadata invalidation/focus refresh.

Tests must use real repository/coordinator/registry contracts for exact A/B/source/manifest preservation, later A Save after B creation, replay after later B edits, changed operation reuse, deleted membership, malformed payloads, empty-project Home, denied roles, and delayed write/readback/factory/admission across Lock/selection/roster freeze. Preserve original adverse results; test double reads are labelled and never called native execution.
