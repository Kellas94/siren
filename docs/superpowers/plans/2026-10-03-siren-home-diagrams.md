## Global Constraints

- Startup: Intro → PIN → Home; manual Lock: separate vault animation → PIN → Home. Returning Home never replays Intro. Reduced motion avoids mandatory animation waits.
- Navigation: at most 64 project locations, 16 view/layout references per location, 12 recent-project summaries per Home response, 64 KiB for the complete navigation file, labels at most 256 characters. Existing project labels retain their tighter 200-character constraint.
- Own data fields only; finite scroll/geometry and nonnegative safe-integer cursor offsets validated against the actual source. Reject malformed/oversized records without replacing prior valid state.
- Home initially receives metadata only. Locked bootstrap contains no real project labels, thumbnails or content. No automatic project creation on unlock. Navigation alone creates no content revision or recovery checkpoint.
- Preserve exact source/diagram/Docs content, private drafts, honest receipts and readonly/recovery restrictions. Continue never silently substitutes a newer source version or a similarly named entity.
- Native sender/frame/role/epoch and selected project are checked before and after awaits. No renderer paths, arbitrary URLs, bearer window IDs, full-project satellite mirrors or stale-envelope retry with a fresh revision.
- Preserve Guided/Mermaid, vector export, Code return paths and existing shortcuts. Audience receives no project chrome, private notes or source content.
- Distinguish visual construction, form editing, source editing and preview navigation. A type card/Guided label must not promise canvas editing or arbitrary node positioning that its actual adapter lacks. C4/imported specialist types remain readable/renderable/exportable when moved out of the primary starter gallery; no existing content is deleted or converted implicitly.
- Physical mixed-DPI/multi-monitor qualification is distinct from simulated geometry. No baseline rewrite, main merge, public release, weakened timeout/oracle or fabricated review ownership. AI remains last; Terminal remains unavailable until its native process-family owner is qualified.

## Review Focus

- Continue names a collected immutable source or deleted document: retain private text, show a reason and fall back to project overview — Tasks 1/2/5.
- Lock/project change happens during metadata read, route loading or diagram commit: reject stale publication and retain acknowledged work — Tasks 2/3/6.
- Home/bootstrap accidentally loads the full diagram bundle or leaks names before PIN: native denied access and measured lightweight entry — Task 4.
- A minimized/crashed view cannot flush: no successful detach/route/Lock/Quit acknowledgement and no false clean-close journal — Tasks 3/7/8.
- Monitor removal or native maximize/attach changes view geometry: titlebar remains reachable and diagram/draft bytes unchanged — Tasks 7/8.

Shared contracts:

- `NavigationLocation` is the approved spec type. Native derives its `projectId`; IPC accepts only `{surface,entityId?,sourceRef?,cursor?,scroll?,layouts?}`. `sourceRef` has exact `sourceId/version/sha256`. No content, path, secret, executable command or caller-supplied epoch is stored.
- `NavigationRecord={schema:1,entries:[{projectId,label,location,visitedAt}]}`. `visitedAt` is a native ISO timestamp after successful navigation. A layout record has exactly `{role,entityId,version?,normalBounds:{x,y,width,height},displayId,maximized,fullscreen}`; use the existing finite native role/ID/geometry validators, including the new diagram role. No old window/frame/epoch grant is persisted; recreating a layout always requests fresh native authority.
- `HomeState={mode,selectedProjectId,projects,continuation,views,capabilities}`. A project summary has `{projectId,label,availability,lastVisited?}`; availability is `cached|verified|missing|recovery`. Cached labels are explicitly metadata, never proof that a current content revision is healthy. Timestamps come only from genuine successful navigation records.
- `RouteRequest={surface:'home'|'diagrams'|'docs'|'code'|'present',entityId?,sourceRef?}`. Native derives selected project, access and target URL. A native transition receipt identifies `{ok,code?,epoch}`; a newly loaded entry reads its receipt through native bootstrap, rather than depending on delivery to its retired predecessor.
- `DiagramIntent={operationId,diagramId,expectedVersion,action:'replace-source'|'update-model'|'update-style',payload}`. Native derives project/epoch; `DiagramReceipt={ok,code?,operationId,diagramId,version,projectRevision,sha256,durability}`. Source, diagram and manifest receipts keep their distinct scopes.
