# SIREN UI: context instead of depth — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the controls a person uses every session visible where the selection is, and stop rendering the ones that cannot affect the diagram in front of them.

**Architecture:** No new shell. The app already has `#nodeInspector`; this makes it persistent and type-true, moves three universal controls onto a flat bar above the preview, and deletes the duplicate routes that existed only to justify hiding things. One frozen capability table decides what renders per diagram type. Nothing is greyed — a control that cannot bite is not drawn.

**Tech Stack:** One self-contained HTML file. No npm, no bundler, no framework, no network. Changes ship as anchor-guarded Python patch scripts in `tools/`, verified by Playwright probes in `qa_exports/` driven against a base and a merged build.

**Spec:** `siren_interface_report.html` (the measured investigation) and `siren_plan.html` (the consolidated 27-item plan). The prototype at `C:\Users\tsinc\Downloads\SIREN_UI_Concept_Prototype.html` is the visual reference for stage 1's shape.

## Global Constraints

- **One HTML file. No npm, no bundler, no CDN, no external font, no network.** `shadcn/ui`, Tailwind and Radix are therefore unusable; their patterns may be borrowed, their code cannot.
- **Nothing may promise what it cannot deliver.** A control that does not affect the current diagram type is not rendered. Never greyed.
- **Nothing may silently lose what somebody wrote.** Any refresh that can overwrite an uncommitted field must carry that field across.
- **No new guard.** Rounds 13 and 14 established this: every problem answered with a gate broke something bigger than it protected. If a task's answer is a new guard, stop and say so.
- **Every task removes something.** A change that only adds has failed before it starts.
- **Patches are anchor-guarded, not SHA-pinned** (they must survive re-application on a rebuilt chain). Every replacement asserts an exact occurrence count. Write with the Write tool — the Bash tool collapses backslashes in heredocs.
- Verification is symmetrical: every probe runs on **both** the base and the merged build. Same answer on both = vacuous, and must be reported as such.

## Task 1: the capability table

**Files:**
- Create: `tools/patch_style_capability_table.py`
- Modify: the app, beside `DIAGRAM_TYPE_STARTERS`
- Test: `qa_exports/verify_style_type_true.js` (written here, used from task 2)

**Interfaces:**
- Produces: `STYLE_APPLIES`, an object keyed by diagram type, each value an object keyed by control id with a boolean. Control ids are exactly the DOM ids: `curve`, `diagramFontFamily`, `diagramFontSize`, `diagramFontWeight`, `diagramPaletteColour0`, `diagramTitle`, `layoutAlignment`, `layoutDensity`, `layoutNodeSpacing`, `layoutRankSpacing`, `layoutRouting`, `legendEnabled`, `numberingStyle`.
- Produces: `styleControlApplies(type, id)` returning a boolean, defaulting to **true** for an unknown pair, so a control added later is loud rather than silently missing.

- [ ] **Step 1: Write the failing probe**

Create `qa_exports/verify_style_type_true.js`. It drives every one of the twenty types through
`#diagramTypeSelect` + the "New starter" control (found **by label** — there is no
`#newStarterButton`), asserts the fixture by reading `#source` before measuring anything, then for
each of the thirteen controls records whether it is rendered and whether the app claims it applies.

```js
const TYPES = ['flowchart','swimlane','state','sequence','architecture','c4','er','class','block',
  'gantt','timeline','kanban','journey','mindmap','ishikawa','requirement','gitgraph','xy','pie','advanced'];
const CONTROLS = ['curve','diagramFontFamily','diagramFontSize','diagramFontWeight',
  'diagramPaletteColour0','diagramTitle','layoutAlignment','layoutDensity','layoutNodeSpacing',
  'layoutRankSpacing','layoutRouting','legendEnabled','numberingStyle'];
// for each type: rendered = the control exists AND has a non-zero box
// FAIL if a control is rendered on a type the measured matrix marks dead
```

The expected assertion count is 260. Report `rendered-but-dead` as the failure.

- [ ] **Step 2: Run it against the shipped build and confirm it fails**

```bash
node qa_exports/verify_style_type_true.js --app C:/Claude/SIREN/releases/SIREN_v1.70.0.html --port 9880
```

Expected: **112 failures** — the measured dead pairs. If it reports zero, the probe is wrong, not
the app. If it reports 260, the fixture assertion is not running.

- [ ] **Step 3: Build the table from the measured data**

Read `qa_exports/style_shot/matrix_*.json`, deduplicate by `(type, control)` — the files contain
repeat runs, and a naive count gives impossible figures like "dead on 28 of 20 types". A pair counts
as live if **any** run recorded `verdict === 'CHANGES'`.

```python
pair = {}
for f in sorted(glob.glob('qa_exports/style_shot/matrix_*.json')):
    d = json.load(io.open(f, encoding='utf-8'))
    for t, blob in d.items():
        if not isinstance(blob, dict) or 'controls' not in blob: continue
        for cid, r in blob['controls'].items():
            pair.setdefault((t, cid), set()).add(r.get('verdict', '?'))
live = {k for k, v in pair.items() if 'CHANGES' in v}
assert len(pair) == 260, 'expected 260 distinct pairs, got %d' % len(pair)
assert len(live) == 148, 'expected 148 live pairs, got %d' % len(live)
```

- [ ] **Step 4: Write the patch script that inserts it**

`tools/patch_style_capability_table.py`, anchor-guarded on `      function structureIsFlowchart() {`
(the same anchor `patch_second_editor_slot.py` used, verified unique). It inserts `STYLE_APPLIES` and
`styleControlApplies` **and changes no behaviour** — nothing reads the table yet.

- [ ] **Step 5: Apply, gate, and confirm nothing moved**

```bash
cp releases/SIREN_v1.70.0.html pending/ui1/app.html
python tools/patch_style_capability_table.py pending/ui1/app.html
node qa_exports/verify_style_type_true.js --app C:/Claude/SIREN/pending/ui1/app.html --port 9881
```

Expected: **the same 112 failures**. This task adds data, not behaviour; an improvement here would
mean the table is being read by something and that is task 2's job.

Also run the syntax gate: two script blocks, `node --check` exit 0.

- [ ] **Step 6: Commit**
