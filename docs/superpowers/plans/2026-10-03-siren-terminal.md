# SIREN Terminal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provide a real project-linked local shell whose existing work continues through Lock while every new input is refused and output remains bounded.

**Architecture:** A native TerminalManager mediates a single utility-process PTY host, explicit directory/profile grants and terminal-role dock/satellite views. Stable native registry/source/coordinator authority supplies project/epoch/mode checks; a qualified process-family guard owns shell lifetime. xterm consumes bounded credited chunks and is destroyed at Lock, while the host continues draining to a capped ring.

**Tech Stack:** Existing Electron 44.5.1 Windows x64; candidate node-pty 1.1.0/OS-inbox ConPTY, @xterm/xterm 6.0.0, fit 0.11.0, search 0.16.0. Candidate admission is an evidence step, not an installed-product claim.

## Global Constraints

- A shell has the user's OS rights. PIN/host isolation is not an execution sandbox. Local PIN remains active; no account backend or AI work is added.
- Gate input synchronously before Lock drain/await/ACK; never interrupt, pause, kill, Ctrl+C or close stdin for Lock. Existing commands/pipelines continue; prompts wait Unlock.
- Renderer has no Node, arbitrary spawn/path/argv/env or direct host port. Every call checks registered caller, frame/URL/role, project, epoch, mode, PIN, session and current lease.
- Only native-granted terminal-role views send input. readonly/recovery refuses execution; role inheritance from a shared URL is forbidden.
- Directory is explicitly chosen and canonicalized; no implicit cwd for virtual projects and no SIREN internal Data/runtime directory as cwd. Source bytes/versions remain SourceRepository authority. No autoRun or automatic command replay.
- Exact budgets: 8 sessions; 4 MiB UTF-8 ring each/32 MiB total; 32 KiB output/input message; 256 KiB unacknowledged output/input queue per view; 2 MiB total host-to-main output credit; 10,000 scrollback lines; dimensions 2–500 by 1–200; 4 KiB retained VT control sequence; latest 256 input receipts.
- Host always drains output; backpressure stops delivery, not PTY. xterm callback returns credits. Locked/unattached output stays in the native ring. Truncated history is explicit and replay sends zero input.
- Native addon pin/load/build/ABI/helpers/licenses/ownership must be proven in actual Electron 44.5.1 x64 and packaged output. No development-Node-only qualification, unknown notice admission, invented evaluator approval, public source/release, or compiler requirement for users.
- No commits are requested in this preparation. During implementation, follow the coordinating user's current commit/review instructions; do not commit this agent's documents independently.

## Review Focus

- Output/protocol reply arrives after Lock with an old attachment: zero PTY writes, even while source drain fails — Tasks 2/4.
- A selected directory is replaced, disappears, contains quotes/Unicode, or redirects into owned blobs: explicit safe refusal and no fallback — Task 3.
- A slow or crashed renderer receives flood output: bounded memory, meaningful gap and responsive input/Lock control lane — Tasks 2/4.
- Child escapes its console or host/main crashes before cleanup ACK: qualified owned-family lifetime and no kill-by-name/PID-only recovery — Tasks 1/2/5.
- Locked terminal tail contains device queries/OSC52/huge unfinished sequence: display-only bounded replay and no native/clipboard input side effect — Tasks 2/4.
