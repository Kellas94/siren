## Traps that have produced false results in this codebase

Each of these has already fooled someone here. None is hypothetical.

  - **Node ids carry a render timestamp** (`t_flow_1787588656142_5-flowchart-A-0`). Any comparison
    built from a raw id differs after every re-render, so "it changed" is meaningless. Strip the
    prefix.
  - **`getBBox()` on an SVG `g.node` is in the group's own coordinates.** A node that moved reports
    an unchanged box; position lives in the transform. Use screen rects.
  - **A control inside a closed `<details>` can be neither scrolled to nor focused**, and `.focus()`
    on it fails silently. It can still report a non-zero size. "Visible" is not "reachable".
  - **The application is one inline `<script>`**, so a DOM text walk finds any sentence in its own
    source code. Reject SCRIPT and STYLE nodes or you will "find" text that is not on screen.
  - **Coverage measures what you touched, not what is dead.** A run that clicks Export and then
    immediately closes the dialog will report the entire export subsystem as unreachable.
  - **`hidden` in the markup does not mean never shown.** Most dialogs and menus are authored hidden.
    Some elements that look like dead controls are load-bearing state stores — one `<select>` in this
    app is invisible and its `.value` is where the diagram's direction is actually kept.

## Declare a positive control

Before you accept any claim of the form "X does nothing", exercise something comparable that does,
in the same run, and report both. A probe that reports zero everywhere is usually broken, and this
is how you find out which one you are holding. Two probes were caught this way in the last week; in
both cases the app was fine and the instrument was lying.
