# Native catalogue append — transaction preflight

Author: Codex `/root/media_batch_review`, 2026-10-07. Read-only source analysis for approved catalogue plan Task3; **not implementation, independent runtime approval or release qualification**. No tests, probes, GUI, build, package, CI, commit or product edits were executed for this report. Earlier reports and adverse receipts remain unchanged.

## Recommended small API

Keep the renderer request exactly `{entryId,title,operationId}`. Reuse `createDiagramCatalogueContract().normalizeRequest` in main; resolve its trusted entry again in the native transaction. No renderer-provided project, ID, source, version, diagram, root, mode or capability.

Add one finite coordinator action, for example `kind:'catalogue',method:'createDiagram'`, with a corresponding `DomainRepository.appendCatalogueDiagram(request,scope)`. These names are proposals. Do not extend existing-entity `applyDiagram` into an implicit create, expose an arbitrary FIFO callback, or relax existing domain grant inclusion. Main supplies a trusted UUID allocator to the repository; allocate once **after selected-history replay lookup inside the queue**, not again on retries. The UUID is output identity, not part of the logical request that must be stable on retry.

Return a finite native persistence receipt containing operation/project/entity identity, historical creation revision/version/hash and actual durability. Keep current membership/current entity version/hash separate. An exact replay after a later edit must not present historical version1 as the current editable version. Main's external result separates `creation` from `opening`; opening refusal after durable creation must never imply that nothing was created. Refused/revoked callers receive no late private window or newly disclosed private metadata; main can retain the operation identity for an authenticated later retry.

## Concrete reuse and transaction order

1. Main captures the authentic sender/frame and project/epoch/transition identity. Diagram origin must be an admitted current working editor; Home uses genuine `capturePrimary` and exact Home URL under a narrow creation action, preserving its empty entity grant. Normal schema2, activation/PIN/account state, mode, roster/admission state and transition fences remain required. Readonly Diagram, other workspace entry URLs, Code, Docs, Presenter and Audience do not acquire authority from their read/edit grants.
2. Coordinator queues the finite action on its existing `#tail`, accounting for pending requests, request bytes and activity generation. Explicitly reject **every** `flushNonce`, including a genuine private ticket. Reject paused creation. Capture transition generations and latch revocation: pause/resume or roster freeze/rollback must not make an already-revoked operation current again merely because the same source/project is visible later. Existing `registry.isCurrent` proves captured native handles/epoch/ID inclusion; it is not alone a proof that no intervening barrier occurred.
3. Inside the FIFO, call `selectedManifestHistory`, recheck scope, require verified current schema2, then resolve replay or create against that actual selected revision. `src/sources/manifest.mjs:146,164` already gives selected ancestry and exact historical `commitManifest` replay. History excludes unselected orphans, checks parent hashes and deduplicates identical retained records. Use it rather than scanning arbitrary revision files for an operation ID.
4. Validate the **raw** active `diagrams` container and unique valid IDs before append. `workspaceEntities` is only a roster: it skips invalid entries, deduplicates IDs and returns empty rosters on parse failure. It cannot prove a well-formed or empty project. Recommend absent `diagrams` as an explicit valid empty-code-project case only; reject null/object/malformed entries/duplicate IDs instead of normalizing or truncating. Keep unrelated imported fields opaque; do not run a whole-project sanitizer over them.
5. Append a minimal native diagram `{id,name:title,source:trustedEntry.source,sirenNativeVersion:1}` with only additional fields actually required by the frozen diagram contract. Do not copy active styles, presentation, comments, layout, source references or renderer state. Validate the new object without rewriting it. Trusted catalogue source is finite literal data; current catalogue `renderQualification:'pending'` is not runtime rendering evidence.
6. Reuse `domain.mjs:71` active-envelope selection: update only the actual primary storage string, import `state`, or direct workspace. Preserve all unrelated storage strings, unknown JSON values, array order, existing entity versions, Code/Knowledge/source pointers and source reference provenance. Preserve JSON values and exact opaque strings; enclosing manifest JSON necessarily changes and is not byte-identical. Pass the unchanged source reference set to `commitManifest`; its canonical ordering is existing behavior.
7. Commit once with the read revision and guarded ProjectStore/SourceRepository adapters. A conflict is refusal; never rebase the stale envelope. Guard after validator/read/commit/recovery-related awaits and final readback. `commitManifest` checks write access and ProjectStore rechecks at `before-select`; the historical replay branch verifies sources/durability but still needs the caller's post-await scope guard. A failure after selection may leave committed bytes: retain truthful identity/uncertainty and allow exact replay rather than asserting rollback.
8. Verify selected readback/new entity hash and actual durability. Refresh main `snapshot` and `bootstrap.snapshot` from verified **current** reread as existing domain adapter does (`main.mjs:492–502`), without `selected()`, selection generation reset, epoch retirement, global preparation or repainting old editors. An unrelated successful append is not a version-change event for the originating diagram.
9. Exit the FIFO before native window creation/admission. `NativeDiagramEdits.admit` (`diagram-edits.mjs:28–34`) awaits `owner.invoke(readDiagram)`; calling it inside the owning queue deadlocks. Track the full external append/open/admit operation in main `writes`, while persistence alone occupies the owner FIFO. After each factory/read/admission await, recheck originating scope plus actual fresh frame/membership. Show/send view-ready only to the genuinely admitted fresh view. Discard partial owned views using the existing asynchronous destruction path; destruction failure fences the shell. Do not roll back committed project data because opening failed.

## Replay identity and opaque marker preservation

Use a distinct creation marker, not `sirenNativeEntityOperation` used by current mutation replay. Bind schema/action/project/operation request hash, catalogue version/reference SHA, entry ID/source SHA, new ID and exact historical new-entity hash. The request hash binds exact validated title and resolved trusted catalogue definition; changed title/entry/definition under the same operation is `OPERATION_CONFLICT`.

On replay, require exactly one matching selected creation proof and validate its historical minimal entity/version/hash and catalogue identity. Call `commitManifest` with **the historical** base revision, original parsed metadata, original source refs and operation ID. Its request hash includes raw `JSON.stringify(metadata)` bytes; rebuilding historical metadata from current state is not exact replay. Return that historical persistence proof without selecting it over later revisions. Read current membership separately: later edited B opens as current B; removed or duplicate B is not recreated or admitted. Operation reuse by a different action, an unselected orphan, or an opaque lookalike marker is not a new successful creation.

Do not silently overwrite a pre-existing opaque value at a newly reserved marker key. Refuse a collision unless it is strictly recognized native creation bookkeeping that this action is permitted to replace. Preserve unrelated `sirenNativeEntityOperation` and other bookkeeping/opaque fields. Hashes prove consistency/ancestry, not author identity or an independent approval.

## Strong negative cases for root implementation

| Case | Required assertion |
| --- | --- |
| A dirty working editor; append B; later Save A at its original entity version | Exactly one B at version1; A Save succeeds against current manifest; all unrelated data/source bytes/provenance retained; no prepare or synthetic A change. |
| Concurrent same-operation requests / retry after acknowledgement loss | Same creation ID and historical receipt, one append; no duplicate windows without explicit bounded policy. |
| Retry after unrelated edits, B version2, or B deletion | No selected-revision rollback or B reset; historical creation remains separate; deleted B cannot reopen or resurrect. |
| Changed title/entry under same operation; same operation used by domain edit; corrupted or ambiguous marker; unselected orphan | Refusal, no append, no rollback or source writes. Exact selected duplicate parent records retain existing ancestry semantics. |
| Malformed diagrams, duplicate IDs, missing primary storage, marker-key opaque object with nested sourceRef | Refuse rather than infer empty/overwrite; unchanged original manifest and source graph. Valid direct/state/storage envelopes all preserve opaque siblings. |
| Extra/getter/prototype/symbol payload; arbitrary source/ID/path; unknown entry; title160/161 and malformed Unicode | Existing finite normalizer refusal, no UUID allocation/publication on invalid input. |
| Queue saturation/bytes; final manifest just within/over budget; count at/over limit | No hidden bypass, no partial append or truncation; unrelated read/export compatibility unchanged. |
| Block each await: history, validator, source verification, before-select, readback, snapshot refresh, native factory, admission read | Lock/selection/account/frame retirement or roster freeze denies further publication/admission; cleanup exact owned views; committed-before-revocation data remains truthfully retained. |
| Pause then rollback/unlock while queued; equal project/source with replaced admission context | Original request stays revoked through monotonic generation/latch; no revival from boolean current-state checks. |
| Genuine private flush ticket, readonly caller, forged Home URL, Home empty diagram roster | Creation denied for first three; only authentic normal/schema2 Home admitted under new narrow action; existing grants unchanged. |
| Recovery checkpoint refusal / late commit acknowledgement / destroy refusal | Exact selected data and `recovery-degraded` or retained uncertainty exposed honestly; no false clean recovery or successful window cleanup. |
