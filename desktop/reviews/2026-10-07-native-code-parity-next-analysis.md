## Recommended coherent batch: source context and command access

Implement the rank-1 register, readable Compare entry/picker and command disclosure together, with the language descriptor correction where the same metadata contract is extended. It addresses the user's ability to find the right agent/source/version and understand available actions without adding a new execution feature or framework. No new library is justified by these gaps; existing CodeMirror, catalogue, owner and diff worker cover the functional base.

Keep this increment within the existing Home library plus the current Code analysis/toolbar. A permanent in-Code project explorer would require new role-specific metadata authority: `NativeWindowCatalog.#capture` currently admits only the primary workspace (`catalog.mjs:14–16`). Do not expose that workspace bridge wholesale to Code renderers. A future side explorer should use an explicit finite Code metadata endpoint and retain open/read/write authorization separately. This first register increment is useful but must not be presented as the complete approved explorer/release/draft system.

Metadata rules and existing seams to reuse:

- Derive descriptors from the selected verified manifest and existing document Knowledge `sourceRef` associations, using exact sourceId/version/SHA. `NativeCodeDocs.#targets` already demonstrates owned document/row metadata and bounded pagination (`src/windows/code-docs.mjs:30–53`); reuse its validation principles, not its writable-only permission as a readonly discovery grant.
- A source may be documented in several documents. Keep aliases/owners separate and display ambiguity or a count; same filename/hash does not bind sources, nominate one owner or authorize editing another agent. Agent labels are document claims, not proof of runtime use, review approval or certification.
- Separate latest stored source from an older version pinned in Docs. A document linked to v1 does not prove current v2 is documented; represent earlier-version documentation explicitly. Do not silently discard version distinctions while grouping by sourceId.
- Preserve the existing named-independent Unlinked indicator. Distinguish documented-without-agent and documented-with-unidentified-agent only from validated actual metadata; an absent/inconsistent association is not repaired by inventing an agent. Missing metadata uses a truthful neutral fallback.
- Keep the existing 64-row pagination / 4,096-row discovery boundary visible and impose finite descriptor/string/association budgets before returning data. No code bodies, filesystem paths, release snapshots or recovery draft text belong in these discovery payloads.
- Bind comparison labels to the exact stored references returned by the owner. Closing B, changing its stored version/project or Lock must invalidate eligibility/result through existing guards; never resolve B again by display label. Reuse `selectedSourceDisplayName`, `listComparisons`, `submit`, generation fencing and cancel/drain, extending only bounded descriptive metadata.
- Source commands remain distinct: Save source stores a source version; Link to Docs performs the existing explicit association transaction; Compare uses stored snapshots. A menu must not invoke a hidden save merely to enable an action. Source-editor commands should share one finite local dispatch path; no generic main executor, code evaluation or arbitrary route/path bridge.
- Retain native Ctrl+Alt+L Lock and current registered navigation/transfer shortcuts. Do not copy R78's earlier Code-library shortcut or DOM-window move/resize bindings into conflicting desktop commands. Context menu and toolbar need the same readonly/pending/fenced/paused/disposed decisions.

## Acceptance cases for that future batch

1. Two same-named sources with different IDs/agents, same-content sources with distinct owners, one source in multiple documents, no-agent Docs and unidentified-agent Docs remain distinguishable. Search/filter/grouping never changes source bytes, documents, claims or manifests.
2. Standalone import is visibly unlinked; refused linking preserves that state and all bytes. Current v2 with Docs pinned to v1 is not falsely labelled current-documented. Unknown/missing associations remain explicit. Pagination and overflow counts are honest with 4,097 items.
3. Compare entry reveals the existing saved-source mode; B labels distinguish names/doc/version while Details retains exact IDs/hashes. No B window gives an actionable empty state; dirty A remains Save-first, without hidden mutation. Same-named/same-hash sources cannot redirect the chosen comparison.
4. Existing native EOF/truncation/approximation and Cancel oracles remain intact. Closing B, peer save, project change, Lock and stale worker completion cannot publish an apparently current result. Any two-column preview preserves literal Unicode/HTML/CRLF and full stored source bytes.
5. Toolbar, command menu and keyboard exercise the same actual handlers with focus, readonly, pending Save, failed Save and attached/detached views. Menu Escape returns focus; missing actions have readable reasons; Ctrl+Z affects the focused Code draft only. Dark/light/named themes, 1280×800 and 125% zoom retain access.
6. .txt source retains text identity and is not labelled Python; static Python analysis is unavailable with an explanation while text diff remains available. Python highlights and large-source loading/history are not regressed. No interpreter execution is tested or implied.

These are proposed acceptance checks, not test results. New independent qualification should preserve genuine original adverse attempts and actual package/source identities, rather than closing defects by checklist edits.
