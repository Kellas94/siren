## Coherent next implementation batch

Recommend **native export and delivery**: rank 1 plus bounded parts of ranks 2 and 3. It improves Home's central controls and makes current Docs/Present work usable outside the application, without adding another always-visible toolbar or prematurely implementing approval systems and media storage. Put one compact Export action/menu in the shared entity context; options depend on the real saved entity and supported formats. Home gets Export saved backup; Docs gets document export; Presenter gets explicitly private speaker notes. Keep the themes/common shell rather than inventing independent export screens.

Use finite main-process adapters and native destination selection. Bind exports to an actual project/document/deck version, regenerate from that saved snapshot, retain source/image/reference provenance and report unsupported content instead of silently omitting it. New exports are standalone artifacts; original project data remains unchanged. Distinguish saved export from an optional save-then-export action so users know whether unsaved draft changes are included. An HTML export must be inert/self-contained, with no active scripts, remote image fetches or executable imported markup. Archival JSON and a source-aware project backup serve different purposes and should have distinct labels.

Qualification should exercise genuine pointer/keyboard/menu routes, readonly versus own-working views, stale versions, cancellation, dirty-owner preparation/Lock, malformed media/markup and unusual Unicode filenames; reopen/read back emitted files and confirm exact expected cells/images/text/private-note separation. Office/PDF fidelity, new binary storage, review approvals, autoplay and physical display behavior must remain explicitly outside this first tranche until implemented and measured. Current hosted qualification remains a separate process; this proposal asserts no outcome for it.
