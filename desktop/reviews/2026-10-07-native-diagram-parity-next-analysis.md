## Recommended next batch: Diagram edit confidence and typography

Deliver Undo, Redo, compact History and the missing supported font controls as one bounded editing batch. It restores a familiar reference workflow and makes structured edits reversible while reusing the existing transactional save boundary. It needs no new dependency, account, project-history API, or full legacy application startup.

Reuse `SirenNativeDiagramDraft.getDiagram/getStatus/setSource/setStyle/save`, existing `replaceSource`, Guided/Build/Style `commit/isEditing`, source-aware `applyDiagram`, exact saved receipt/version/hash validation, and the current semantic targets. Reuse font and weight allowlists from `SirenNativeDiagramStyle.fonts/weights`; `applyStyle` already respects imported Mermaid typography through `appearance.fontDeclared`. Preserve source-declared colours and that typography precedence.

Required implementation boundaries:

- History is per actual working draft/window, not a rollback of the project journal, source repository, imported agents, peer windows or saved approval records. A restored saved step becomes a new local draft and reaches disk only through existing explicit Save/CAS. Never rewind acknowledged version/hash counters.
- Capture complete admitted source/style transactions, coalesce ordinary typing, suppress recording while restoring, truncate Redo on a genuine new edit, and expose a finite step/byte budget. The reference's 60-step limit alone is insufficient for large strings; an explicit aggregate-byte cap must keep current work intact when old history is evicted.
- Refuse restoration during pending/fenced/paused/readonly/disposed states. Commit or visibly refuse pending Guided/Build/Style fields before a jump; never silently discard unfinished Add/Connect fields. Refresh/adopted external versions must clearly reset/rebase local history rather than restore content at an invented fresh base.
- Presentation authoring shares this draft's `presentationEdits`. Source/style history must preserve those edits exactly and state its coverage; it must not silently include or erase deck/notes history. Do not expand the parent's separate frozen Presenter lot through this batch.
- Route Ctrl+Z/Ctrl+Shift+Z/Ctrl+Y deliberately; never intercept composition or make a focused uncommitted field lose text. Toolbar and History must use the same command path. Readonly views may expose typography values but no mutation authority.
- Add global weight and per-block family/size/weight under the existing Style disclosure. Keep no-selection/source-owned states honest, and preserve untouched node style keys when changing one property. A labelled compact group is sufficient; avoid another permanent toolbar row.

Future qualification should prove exact whole-diagram bytes across Text/Guided/Build/title/style undo/redo/jumps, redo truncation and history eviction; native rendered font effects; incomplete-field refusal; Save/failed-save/conflict; Lock/Refresh/Close; two independent diagrams/windows and attached/detached continuity. Preserve unrelated project/source/deck metadata and use actual pointer/keyboard receipts. These are proposed acceptance checks, not tests run by this analysis.

Walkthrough can follow as a separate small preview batch: reuse `styleTargets`' exact IDs/groups and `onPreview`, clear traversal on stale/invalid/paused/disposed renders, ignore unsupported target sets, and keep viewing actions out of saved content/export authority. Filters and metadata follow after their editing/view contract exists.
