# Sources Task 3: manifest and migration implementation

This is an implementation handoff, not an independent approval or capacity qualification. It covers `src/sources/manifest.mjs`, `migration.mjs` and their two focused test files. Project store, recovery, garbage collection, renderer guards and package integration are owned by the coordinating agent.

## Manifest contract

`verifySourceManifest(snapshot)` validates the schema 2 envelope, project identity, bounded JSON metadata, complete source references, metrics, encoding, newline/BOM fields, provenance and request hash. Thin metadata references are exactly `{sourceId, version, sha256}` in `sourceRef` or `baseSourceRef`. Referenced source content is excluded from knowledge rows, code files and private drafts. JSON-valued storage entries are inspected as well.

`manifestRequestHash({projectId, baseRevision, sourceRefs, json, operationId})` hashes canonical source references and the exact metadata JSON string. Including the operation ID prevents an orphan created by another operation from aliasing selected ancestry. Schema 2 records carry both `parentRequestHash` and `parentManifestHash`; the latter uses the canonical complete parent snapshot, including native checkpoint policy. `manifestSnapshotHash(snapshot)` exposes that exact body identity. Both parent anchors are null for the first schema 2 revision. Only ancestors whose logical request and full body match the selected parent anchors can acknowledge old duplicate operations. Canonical-identical revision files from a failed selection followed by an exact retry collapse to one identity. Missing or ambiguous ancestor proof produces a conflict instead of a false acknowledgment.

`commitManifest({projects, repository, recovery?, projectId, baseRevision, sourceRefs, metadata, operationId, purpose?, fault?})` owns the project writer lock. It reads the exact requested immutable source versions, compares repository-derived complete references, verifies exported hashes and materializes their blobs before publishing the manifest. Sources may have a newer current version. It never nests a repository `commitSource` writer lock. The native-only `purpose` is `workspace` by default or `restore`; it is not a renderer permission assertion. The passed `projects.commit(directory, snapshot, {canSelect})` callback returns true after rechecking project permission and repository access; the store must invoke it after awaited preselection work.

Receipts identify the exact operation, project revision, metadata hash and complete source references. A postselection exception is acknowledged only after full selected-envelope readback. Records with `checkpointRequired:true` remain `recovery-degraded` unless the supplied recovery service proves an exact saved checkpoint. Omitting recovery during a duplicate request does not upgrade degraded durability.

## Migration contract

`migrateLegacySources({snapshot, repository, projects, recovery?})` creates a separate project with the original schema 1 JSON as its retained initial revision, extracts source text and commits its current schema 2 manifest. It does not select, edit or delete the original project. The original project ID/hash and new project ID are returned, together with the selected snapshot and a mapping from original link identities to native pointers. Failure reports `MIGRATION_INCOMPLETE`, its reason and any retained partial new project; it does not admit that project as migrated.

Extraction covers working knowledge rows, immutable release knowledge snapshots, standalone `codeFiles`, linked file aliases, `codeWorkspace.drafts` and the actual `siren-code-drafts-v1` storage key. Existing document/block/row/source/agent/release/draft identities remain metadata. Shared original source identity and identical bytes use one source; separate release identities remain separate even when text matches. Current and backup workspaces resolve their own linked files independently; private persisted drafts use the current workspace. Unchanged JSON-valued library entries retain their exact original string spelling and whitespace.

`remapSourceReferences(metadata, mapping)` supports a Map or object indexed by `sourceId:version:sha256`. It clones metadata, rewrites only exact thin native pointers, and traverses JSON-valued storage entries. Missing mappings throw `UNKNOWN_SOURCE_REFERENCE`. Legacy owner identities and special JSON keys such as `__proto__` remain data.

Schema 1 stores text strings, so migration cannot infer raw encoding bytes that were already lost before this subsystem. Unpaired surrogate strings are explicitly refused instead of replaced during UTF-8 encoding. Runtime-only draft snapshot history arrays are unsupported and cause a retained incomplete migration, rather than being silently discarded. Existing repository raw unsupported source versions can be committed into schema 2 and remain byte-exactly exportable; conversion is required before editing. Unknown source structures that violate schema 2's inline-source guard require explicit handling; the original and initial new-project copy remain intact.

## Verification

Initial failing tests precede both modules (`source-manifest-red.log`, `source-migration-red.log`). Subsequent reproduced failures cover thin-pointer numeric types, backup/current link aliases, special JSON keys, exact library strings, duplicate orphan ancestry, native restore permission and permission revoked in an awaited preselection hook. Their intermediate logs remain in `desktop/evidence` without being relabeled as successful runs.

The focused run `source-manifest-migration-final-focused.log` records **20 tests passed, 0 failed** before the final parent-body regression. `source-manifest-parent-body-red.log` reproduces a failed checkpoint-enabled attempt and selected checkpoint-free retry with the same logical request; `source-manifest-parent-body-green.log` records the corrected final **21 tests passed, 0 failed**. The suite also checks byte-identical original project files, independent source hashes, forged metrics/provenance, stale versions, duplicate ID conflicts, old immutable source versions, unsupported raw bytes, concurrent writers, preselection failure, after-selection failure and degraded checkpoint receipts. No full suite, native probe, commit or package publication was performed by this worker for Task 3.
