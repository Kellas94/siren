## Minimal proposed contracts

1. **Main-owned registry.** Main creates only enumerated local roles: workspace owner, Docs editor/viewer, Code editor, Present controller, Present audience. Each window has a main-issued ID, webContents identity, role, selected-project ID and project/access epoch. Sender/frame/URL/role are resolved from the registry, not trusted from payload. Preserve sandbox, context isolation, no Node integration, denied arbitrary navigation/webviews and denied arbitrary popups. Use packaged local role entrypoints, not renderer-supplied URLs, paths, preload names or document.write payloads. This follows the [Electron sender-validation guidance](https://www.electronjs.org/docs/latest/tutorial/security) and narrow [IPC bridge model](https://www.electronjs.org/docs/latest/tutorial/ipc).

2. **One project save owner.** For the smallest migration, the current workspace renderer remains the model/save owner while native main brokers validated satellite intents and results. A detached window receives only the selected document/source/presentation data it needs, plus authoritative revisions. It must not independently instantiate the full project mirror/autosave. The native coordinator owns durable writes and access checks; the renderer owner retains existing domain validation initially. Moving the full domain model into main is a larger future decision.

3. **Typed intent/receipt.** Proposed shape: request ID, epoch, entity ID, expected entity version/hash, enumerated action and bounded payload. Main derives caller/window/project. Domain validation occurs at the one model owner; one queue commits and acknowledges. Receipt binds request, epoch, entity, project revision/hash and outcome. Duplicated requests must not double-apply. Same-entity concurrent edits refuse or resolve explicitly; different-entity edits serialize without stale full-envelope replacement. Code draft edits remain private; Save to Docs is a distinct explicit source update. Keep a bounded pending-intent journal or equivalent recovery for satellite work if the model owner crashes; an unacknowledged renderer buffer is not “saved”.

4. **Selection and access transition.** A single native barrier prevents new mutation intents, makes every window inert/covered, drains each dirty editor and owner queue, awaits durable recovery receipts, then commits Lock or project change. No locked bootstrap or status contains project data. A failure retains work and reports precise failure; it cannot claim completed Lock/close. Project switch increments epoch, invalidates old grants for satellite mutations, clears old data/late queued events and rebinds or closes affected windows. Existing grants Set is not sufficient proof of current selected-project ownership. Audience windows must blank/close and discard cached slide/SVG/image data on Lock or switch.

5. **Close semantics.** Closing a satellite flushes its intents/private recovery and closes that window, not the whole app. Quit/closing the workspace owner initiates the all-window save barrier; do not record clean-close while any editor is unacknowledged. Decide explicitly whether workspace Close quits all windows or leaves a supported owner alive. Minimal first iteration: owner Close means coordinated Quit; satellites can close independently. Owner crash must leave no satellite capable of blind saves; retained pending work and explicit recovery are required. Shortcut/menus route to focused-window role, with global Lock/Quit overriding role commands.

6. **Presentation transport.** Controller and audience are separate roles. Audience gets a bounded presentation-only payload; no full workspace, credentials, private drafts or file paths. Sequence/epoch discard stale frames, and backpressure coalesces visual updates instead of queuing full SVG/image snapshots every 45 ms. Presenter Next/Previous are typed intents to one controller. Lock cancels timers/transport and blanks every screen.

7. **Geometry.** Store normal bounds in DIP, display identity and maximise/fullscreen state as non-content preferences. Clamp against current work areas at reopen, monitor removal, metrics change and DPI transition; keep titlebar/control area reachable. Provide a keyboard “Bring window back” action. Do not reuse Code's innerWidth/innerHeight clamp for OS bounds. Electron documents display removal/metrics events and DIP conversion in its [screen API](https://www.electronjs.org/docs/latest/api/screen); actual unplug/mixed-DPI behavior still needs native qualification.

## Verifiable risks and required probes for the future implementation

| Scenario | Necessary oracle |
|---|---|
| Docs and Code edit different entities simultaneously | Both exact changes survive one canonical model; acknowledged disk revision/hash verified; no full-bag replacement |
| Two views edit same source; delayed or duplicated intent | Explicit version/hash conflict or idempotent receipt; no silent overwrite/double-apply; attempted text retained |
| Lock from any window while another is dirty/minimised/unresponsive | All windows covered; native PIN gate; no snapshot/slide data; exact durable receipts or honest retained failure |
| Change project/restore while old intent or visual frame is in flight | Old epoch refused, no cross-project save/render, existing original bytes preserved |
| Satellite close, owner Quit, renderer crash during save | Role-correct close; no premature clean-close; pending text recoverable; unknown writer/access still fails closed |
| Monitor unplug, negative coordinates, mixed 100/150/200% DPI, fullscreen | Every native window reachable, geometry sane, no source loss; actual multi-monitor movement captured |
| Unregistered same-origin frame, forged role/window ID, arbitrary URL | Sender/method refusal; no privilege gained by origin alone |
| Present audience/background window during Lock | Blank actual audience on each monitor, queued frames cannot repopulate locked state |
| Large documents/code/media and several windows | Measured input latency, memory, IPC queue/bounds, save/recovery time; cancellation preserves exact bytes |
