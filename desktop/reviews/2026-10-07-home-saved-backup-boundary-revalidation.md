## Smallest coherent correction

Connect only **Home → current selected saved backup → native Save dialog → durable publication**. Preserve existing classic and schema-2 formats, exact source bytes and existing lifetime protections. Do not add Docs/Presenter exports, a general delivery framework, arbitrary renderer project/path/body inputs, save-all preparation, or a new Show file capability in this correction.

The earlier delivery analysis correctly identified the Home authority and source-aware boundaries, but its statement that legacy exportBytes is unguarded is now stale. Current exportBytes accepts an isCurrent callback, checks before and after the chooser, fences every atomic pre-rename phase, requires pending cleanup, and tracks the actual publication in `writes`. Its accepted rename completes readback and is drained before Lock/selection confirms. Those mechanics can serve a new Home authority callback without changing the legacy URL gate or old authorization. The SVG exporter does not need to be generalized for this bugfix.

Use a finite dedicated Home backup route, for example `siren:home-export`, whose preload method submits an empty request. Capture the genuine Home sender/frame through HomeAuthority, additionally require exact Home URL, and derive selected project internally. Validate all extra fields away by refusal. The existing generic Home navigation invoke contract expects navigation epochs, not export receipts; do not masquerade as createProject/continueWork or add exportProject to generic `homeMethods`. A small dedicated request/result adapter is clearer than relaxing that contract.

The main service should capture the Home grant/current project ID/mode/selection generation before awaits, then read that selected project's verified saved snapshot. Schema 1 exports exact snapshot.json bytes; schema 2 calls the existing source-aware serializer, which verifies each full ref and source hash/length. Recheck authority after the project read and source serialization and before the chooser. Never authorize by the historical legacy `grants` set or a renderer-supplied ID. Never synthesize metadata-only JSON for a source-backed project.

Reuse guarded exportBytes with a Home-specific current predicate incorporating the captured Home grant plus synchronous `pinTransition`, account/selection/close/quiescence/failure gates. HomeAuthority already binds native sender/frame, URL, unlocked state, epoch, selected ID, mode and generation. Its invalidation prevents an old chooser becoming valid again after Lock→unlock or selection→return. Including transition flags prevents publication even before asynchronous preparation reaches its invalidation call. Do not change or broaden captureLegacyExportAccess, which intentionally requires the legacy app URL.

## Saved, readonly, chooser and publication semantics

- **Saved means captured saved revision.** Do not prepare/flush editors, change selection, retire services or save unsaved drafts. Capture/read one real saved revision and return its bounded revision/hash/format receipt. Later ordinary saves can produce a newer revision without changing the bytes of this labelled captured export. Persisted draft/history/opaque metadata already in that saved snapshot remains exact; unsaved working copies and out-of-manifest private Code drafts are not silently promoted or included. UI states this before/while exporting and on completion.
- **Readonly is exportable when the saved project can be verified.** The action creates a chosen output, not a project mutation. Preserve the existing readonly export behavior. Recovery mode does not authorize reconstruction or omission: if the selected saved snapshot/sources cannot be verified, refuse and retain existing recovery routes. No selection means no chooser. A verified selected saved record may be exported without gaining write access.
- **Chooser waiting is not a writes drain.** Track publication, not the unanswered OS dialog or the whole operation, so Lock/selection/close can revoke a pending chooser without waiting for user response. Main should allow at most one pending Home export/chooser, with finally release; UI busy alone is not a security bound. Native Lock remains available while Home export waits. After revocation, even return to the same project/PIN cannot publish from the old chooser.
- **Cancellation is a real finite result.** CANCELLED leaves no staging/publication and preserves selected state, original files and drafts. Do not report cancelled as successful export or generic navigation success.
- **Pre-rename revocation cleans only the new pending file**, preserving any existing destination; failed cleanup stays a real rejected publication/drain failure. **Accepted rename is not rolled back** by later Lock: finish exact readback and let the existing drain join it. A response after retirement may be suppressed/refused, but its UI must not falsely guarantee that no file was committed. Do not delete a user's accepted destination to compensate for a stale response.

The finite result can contain success, captured revision/snapshot hash, format, output byte count and digest where available; it must not contain the snapshot/body/source bytes or filesystem path. Keep source read/validation/budget, cancelled, revoked and publication failure messages distinct enough to describe the actual outcome. Reusing the existing publisher's success-only result does not justify fabricating an output digest: derive one from exact serialized bytes and actual durable write result if the new receipt promises it.

## Size/round-trip boundary

Home import currently caps wire input at 64 MiB; source-bundle parser uses the same wire maximum, per-source 32 MiB and decoded total 256 MiB. Existing source export serializes a verified snapshot plus base64 and has no aggregate wire preflight. Do not adopt SVG's 2 MiB cap or silently produce a newly advertised backup that its paired importer refuses.

For this route, preflight schema-2 serialized wire size before loading all sources: UTF-8 byte length of JSON `{format:'siren-source-bundle',schema:2,snapshot,sources:sourceRefs.map(ref=>({ref,base64:''}))}` plus the checked sum `4*Math.ceil(ref.utf8Bytes/3)`. Base64 needs no JSON escaping, so this bounds the actual wire for verified unchanged refs. Reject over 64 MiB with a truthful backup-budget result; still compare actual serialized byte length afterward. Avoid allocating a huge placeholder array/string beyond existing ref/metadata budgets. Schema-1 exact JSON stays within its existing cap. Preserve the export format and parser's frozen semantics; changing aggregate import policy is separate work.
