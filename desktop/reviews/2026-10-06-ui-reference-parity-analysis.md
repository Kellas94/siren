## Recommended direction

Preserve the visual language and functions of the HTML reference while consolidating the desktop work experience. The alternative of only reskinning the native windows does not address the documented navigation and authoring gaps. Making the old full-envelope editor the sole desktop editor would also leave the approved large-source and native-window requirements unresolved.

- A shared, compact application frame: SIREN identity, project, Home, Diagrams, Docs, Code and Present, plus Find, theme selection and window controls. Contextual commands sit with the current module; secondary actions remain discoverable in labelled groups/menus. Do not put every document or diagram action on Home.
- Home is the entry/resume surface: Continue, projects, recent items, open/minimized windows and useful module entry actions. Switching into a module should lead to its working environment, keeping the common navigation available.
- A theme gallery based on the existing 39 themes, with a small initial selection and the rest discoverable. Colours, typography and appropriate background treatment must work in attached and detached windows. Respect reduced motion, large-source performance and readable focus/contrast. Application themes must not overwrite imported Mermaid colours or immutable exported/public presentation content.
- Restore Docs, Diagram and Present functionality in measured groups, with a per-function migration/access checklist. Preserve real saves, conflicts, private drafts, exact source versions and Lock/Close coordination. An attractive toolbar with disconnected actions is not feature parity.
- Attached and detached views should use the same module components and command groups. Audience remains a public presentation surface; it must not gain project/editor/private-note controls merely to match the working application frame.

Suggested implementation order: reliable central navigation and project context; common named themes; Docs authoring/register/formatting and review access; Diagram studio commands/export parity; presentation studio; remaining Code access/parity. This order is a proposal to incorporate into the approved plans, not a claim that the work has shipped. New visuals should be assessed against these supplied references before product changes are admitted.
