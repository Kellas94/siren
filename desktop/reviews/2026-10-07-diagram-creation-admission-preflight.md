# Diagram catalogue creation and admission — independent preflight

Author: Codex independent reviewer `/root/diagram_history_final_review`, 2026-10-07. Read-only source analysis following the discovery preflight. No implementation, tests, build, GUI, commits or approval. The proposed APIs below do not exist yet. Existing hosted pan and historical Save/Attach causes remain open; current Docs Activity qualification is unrelated.

## Finding and recommended boundary

A finite catalogue can create a separate saved Diagram without preparing the whole workspace, but **there is currently no authority that a Diagram satellite can reuse to do this**. Add an explicit main-owned create-from-catalogue operation, serialized by the existing WorkspaceCoordinator. Persist only a new entity derived from a trusted catalogue entry and a bounded title. Then admit a separate working Diagram window. Do not reuse Home document creation, existing-entity Domain apply, whole-workspace save, or the renderer's generic window-open route.

Browsing and creation must preserve the existing editor's source, pending fields, history, entity version and saved bytes. A new project manifest revision is legitimate; incrementing every existing Diagram version or replacing their renderer contexts is not necessary.

## Concrete proposed owner contract

Use a small new main-owned service, for example `DiagramCreation`, and an explicitly named coordinator action `createDiagramFromCatalog`. These names are design suggestions. The IPC accepts only `{entryId, title, operationId}` with exact own-data fields, finite strings and no project path, entity ID, source, theme, whole diagram, snapshot, expected existing-entity version or renderer capability. The entry ID resolves against a versioned trusted finite catalogue in main. Its source is literal, bounded data; choosing an entry must not execute renderer code or invoke legacy mutation handlers. Hash the resolved catalogue definition into the operation request identity so a later catalogue revision cannot silently change a retry.

For the initial satellite entry point, require a genuine current Diagram main frame, normal writable schema-2 selected project, an existing current Diagram membership, and actual `workingDiagrams.isWorking(grant)`. Check PIN/account/selection/view-close/barrier/native-failure state before queueing and again through the scoped write guards. This is an explicit new project-level append permission attached to an admitted working view, not permission to edit or read arbitrary sibling entities. A read-only view may browse inert catalogue data; do not assume its current read grant authorizes creation.

Home is justified as a second narrow entry point because a project with no Diagrams otherwise cannot reach a Diagram satellite. Implement it only with genuine Home `capturePrimary`, exact Home URL, normal/schema-2 selected context and the same explicit creation policy/owner operation. Its entity grant should remain empty. The current main access branch permits Home only the readonly action, so this exception must be deliberate and tested; calling the existing Home document-create transition is not a substitute. Other workspace roles, Presenter and Audience need no new authority.

Within the FIFO: read verified selected manifest ancestry, reject malformed/oversized diagram containers, resolve the catalogue entry, generate the new ID in main, and append a minimal validated new Diagram with initial native version 1. Validate the actual new object with the frozen product contract; do not assume an imported full object or every legacy template is safe merely because it rendered once. Preserve all existing entities, sourceRefs, presentation/release metadata and opaque siblings in the active envelope. Do not introduce inferred global styling. Apply explicit entity-count, final manifest and request budgets; existing finite request sizes do not by themselves bound an imported diagram array scan.

Commit against the manifest revision just read using `commitManifest`, scoped canSave/canWrite and guarded readback. A project-revision conflict must not be repaired by resubmitting a stale whole envelope with a newer base. Readback must verify the new entity identity/hash and actual durability. Existing diagrams retain their exact JSON content and versions, so their pending later Domain edits can still use their original entity CAS against the then-current manifest.

Operation replay needs a distinct provenance marker containing the selected project, action, request hash, resolved entry identity, new entity ID and entity hash. Find it in verified selected ancestry, verify the historical object and replay the exact historical `commitManifest` request. `commitManifest` already returns that historical receipt without selecting it over later work. Never append twice for the same operation, manufacture a clean receipt, accept a loose imported marker, or overwrite a later edit of the created Diagram. On replay, return the historical creation identity separately from current availability; opening requires the entity still to be an admitted member of the current snapshot. A removed entity must not be resurrected by opening or retrying creation.

## Admission and refresh sequence

1. Complete the queued durable append and update main `snapshot`/`bootstrap.snapshot` from a verified current reread. Do not call `selected`, `activateWorkspace`, epoch invalidation, prepare or existing-window reload. Catalogue rows remain metadata, not grants.
2. After the queue operation resolves, main may open the newly created ID through `WindowRegistry.openView`, recapture the actual new frame and call `workingDiagrams.admit`. **Do not await that admission inside the same FIFO operation:** admission calls `owner.invoke(readDiagram)` and would queue behind itself.
3. Recheck creator identity, epoch, transition state, current entity membership and working admission after asynchronous steps. Send view-ready/show only under the actual fresh grant. Dispose any incomplete native surface using the existing refusal cleanup pattern. Keep the entire external creation/admission operation in tracked `writes`; keep the persistence portion in the owner queue. A transition can freeze admission after persistence: report creation retained and opening unavailable, rather than deleting the committed diagram or retrying with a fresh operation ID.
4. Surface persistence and opening as separate outcomes. A finite retry/open action must be tied by main to this creation result and current membership, not arbitrary renderer-supplied sibling IDs. Lost acknowledgements must recover with the same operation identity. Recovery-degraded durability must stay explicit.
5. Home can refetch its metadata catalogue on a bounded invalidation/focus refresh. Neither notification nor a new catalogue row expands the originating Diagram grant. Existing native Diagram subscriptions are entity-scoped and report version changes; do not broadcast a fabricated change for the untouched origin. The new window legitimately changes registry window membership generation; the append alone does not require replacing existing grants.

## Pending-field preservation is also a UI requirement

Avoiding Save/prepare is necessary but insufficient. Current Guided editor `blur` calls `finish(true,false)` and can apply a valid pending source edit; Style input `change` calls `commit()`. Moving focus into a catalogue dialog, its search/title field, or the newly shown native window can therefore mutate local draft/history even if the creation IPC never reads the editor.

Define and verify a scoped focus/pending-field policy before implementing the UI. Catalogue entry and navigation must not call existing `guidedView.commit`, `styleView.commit`, Build commit, Inspector apply, or draft refresh/dispose. A pointerdown guard alone does not prove keyboard, programmatic focus, window activation or IME preservation. Recommend explicit `beginExternalInteraction` / `suspendImplicitCommit` contracts in Guided and Style: acquire the lease before any pointer, keyboard or programmatic focus transition; retain the actual pending DOM, values, error markers, source binding and history; suppress only the resulting implicit blur/change application. Keep explicit Apply/Cancel semantics meaningful. Do not reconstruct pending values from saved diagram bytes or use controls that merely do nothing while editing. This is a proposed, unimplemented contract.

Cancellation must restore the original still-current field focus/selection before releasing suspension, otherwise the release can re-enable the very blur/change commit it was meant to avoid. On successful new-window opening, do not steal focus back from that window. Keep the old editor's pending state protected until its genuine return-to-editor interaction can restore focus and release the lease; use an idempotent lease owned by that controller/context, not a permanent global boolean. Multiple open/close gestures must not stack leaked leases. If the old field or context was genuinely disposed, release without restoring or recreating private DOM. A remote version notification while the catalogue is open must retain the pending source binding and existing stale/conflict behavior, not silently reload or rebase it.

Lock/prepare/disposal must close and retire catalogue interactions, reject late create/open replies and prevent delayed focus restoration into retired or hidden private content. Suspension cannot turn a real later Save/prepare into a clean no-op or bypass its validation: define the handoff to the existing explicit commit/flush lifecycle separately. Composition state must not be committed, discarded or guessed because catalogue focus moved; verify the entry guard and return path with actual composition events. These are implementation blockers for the preservation promise, not evidence that an unimplemented catalogue currently fails.

## Required acceptance before runtime qualification

These are proposed checks, not checks executed in this preflight:

- Open catalogue/create while valid and invalid Guided/Style/title/Build/Inspector fields are pending; cover pointer, keyboard, IME and new-window activation. Original source, field values, undo/redo position, dirty state and saved entity hash/version remain exact.
- A saved A version N and dirty A version N coexist with creation B version 1; a later normal Save of A succeeds without losing B or unrelated source references/opaque/presentation data.
- Repeat exact creation before/after later B edits and unrelated manifest writes; one B exists, historical receipt remains truthful, current bytes never roll back. Changed entry/title for the same operation is refused. Deleted/ambiguous membership is refused at open.
- Exercise descriptor/prototype/extra-field payloads, finite catalogue/container limits, foreign/readonly/Home-spoofed callers, stale frame/epoch and no-diagram Home bootstrap.
- Delay commit/readback/factory/admission across Lock, selection and roster freeze; no new data surface survives revocation, no deadlock, no untracked mutation, no fake preparation proof. A committed creation with failed opening remains discoverable after valid recovery.
