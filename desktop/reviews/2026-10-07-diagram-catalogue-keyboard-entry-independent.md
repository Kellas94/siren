This original finding remains separate from correction evidence.

`mount()` creates the view and listens for Escape on `host`, but never puts keyboard focus in that host. When the Diagram shortcut opens the nonmodal panel while the active field remains outside it, a following Escape bubbles through the old field's ancestry and never reaches the host listener. The view stays open. A later shortcut/toggle can therefore close that already-open panel instead of opening a new one. This is an independently demonstrated event-routing defect; no source mutation or rendered-diagram failure is inferred.

My independent finite DOM/VM probe dispatches Escape from `document.activeElement` through that element's actual simulated parent chain, rather than invoking the host handler directly. On the retained original source, keyboard entry stays on the outside input and Escape while the page is loading does not close the view. The 9-probe matrix gives **5 passed, 4 failed**, exit 1, no cancellation/skip. Failures cover synchronous initial Cancel focus, active-element Escape routing, readonly initial focus and fresh reopened focus; these are manifestations of the same omission. Other probes pass, including no focus stealing from an already-open title, no late-page focus stealing, pause/dispose stale replies, composition handling when focus is deliberately in the host, and disabled/disposed admission.
