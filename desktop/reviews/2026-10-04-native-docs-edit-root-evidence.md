# Native Docs editing and preparation — implementer evidence

Written by the implementing coordinator. This report is not an independent review, a release approval or an assertion that the complete native-workspaces plans are finished.

Native Docs now opens a separate explicitly admitted working window for a selected schema-2 document. The editor supports title, headings and canonical plain-text blocks, including Add/Remove and explicit Save/Ctrl+S. Existing advanced blocks, agent metadata, historical release authors/verdicts, source pointers, other documents and diagrams remain exact. Rich formatted text and specialized Knowledge/table editors remain read-only here. Schema-1 native documents remain read-only pending explicit migration.

A title plus blocks uses one scoped `replace-content` operation and exact document CAS. Main validates both pieces through the unchanged frozen product validators in an isolated hidden window with no project/PIN preload, persistent profile, network or permission grants. Failed validation is refusal, never silent normalization. Genuine subscriptions disclose only document ID/version/project revision; clean idle views refresh and dirty/conflicted views retain local text with separate saved review and explicitly confirmed reload. No conflict merge, fresh-version retry or guarantee for unreceived keystrokes was added.

Working Docs participates in the existing finite native preparation ticket. Closing a view and Lock save its dirty draft before sealing actual owner receipts. Failed preparation restores visible retained content; rollback during an in-flight save releases the UI pause while pending/fenced states continue refusing edits. Readonly status remains explicit after rollback.
