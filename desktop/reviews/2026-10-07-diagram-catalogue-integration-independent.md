## Static integration observations and limits

Main separates browsing from creation: readonly/recovery browsing may remain available while writes require normal writable schema-2 mode and either the empty Home workspace grant or an admitted working Diagram. Lifecycle transitions, selection quiescence, lock, and native failure refuse both paths. These predicates do not themselves authenticate renderer claims: `NativeDiagramCatalogue` uses actual registry sender/frame capture, role/entity bounds, and owner capture guards. The main channel tracks the complete service promise, including append and opening/admission, in `writes`; it refuses an extra private flush identity. Both preloads expose only frozen `getPage` and `createDiagram` functions and do not forward a second caller argument. Home notifications are payload-free signals at the renderer boundary.

Current frozen service guards are private main-process objects, not user-authored metadata approvals. It bounds pending calls to 64 and deduplicates opening promises by project/operation. It verifies the full derived creation marker around awaits and before/after showing. Main's domain adapter uses guarded real ProjectStore/SourceRepository plus recovery/validator and rechecks scope before replacing the shared snapshot. Core marker/admission cleanup has its own earlier independent adverse report and separate successful recheck; this integration review does not replace them or fabricate another core run.

Diagram focus acquisition is wired on capture pointerdown and the Tab path, with a direct shortcut fallback. The focus and view are retired before source/draft replacement, at prepare, and at pagehide disposal. The catalogue opening path has no Save/flush call. Existing all-view prepare still commits staged fields and performs its original explicit flush protocol; opening the catalogue does not introduce that protocol. Context identity uses the actual draft object. Successful creation closes with `restoreFocus:false`; cancel closes with `restoreFocus:true`. The source/view payloads are finite and rendered as text; selected source is not sent back as write authority.

Home covers increment its serial, clear dialogs and dispose the owned catalogue. The catalogue enabled closure binds its exact current view object; old getPage/create replies cannot remount a new Home. Catalogue-change signals defer refresh while the catalogue is open, preventing notification-driven disposal before the user sees the create result. Head script startup is deferred to DOMContentLoaded; shared icon definitions are loaded by the external shell script before that event. Builders prefix focus/view definitions before the Diagram controller and preserve the existing three-inline-script structure.
